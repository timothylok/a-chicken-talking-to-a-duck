# Stock automation

Moved out of `CLAUDE.md` on 2026-08-27 — it only matters when working on the stock
pipeline, and it was ~3.5k tokens of every session's context. Per-tier detail also
lives in the memory files (`stock-fundamentals-report`, `stock-earnings-report`,
`stock-valuation-report`, `stock-technicals-report`, `stock-risk-flags-report`,
`stock-risk-dashboard`, `stock-day-range`, `stock-watchlist`,
`stock-report-retry-and-alerting`); this file is the architectural overview.

- **Stock analysis** — `STOCK_ANALYSIS` command (`分析股票 AAPL`, prefix-matched free text like `CREATE_REMINDER`; ticker regex-extracted in code, no LLM needed for that part) fetches price/50-200d SMA/RSI(14)/day-week % change from Yahoo Finance's unauthenticated chart JSON endpoint (`query1.finance.yahoo.com/v8/finance/chart/...`, called directly via `urllib` — no `yfinance`/`pandas`/`numpy` dependency) and has local Ollama narrate a Cantonese 買入/持有/沽出 take (explicitly framed as not investment advice). Voice/Slack/text only, not the public web chat. `SPCX` = Yahoo-listed "Space Exploration Technologies Corp." (SpaceX), confirmed live/tradeable via the API 2026-07-27 but too recent (first trade ~mid-June 2026) to independently verify what kind of instrument it is.
- **Pine Script generation** — `PINE_INDICATOR`/`PINE_STRATEGY` commands (prefix-matched free text, e.g. `pine indicator: 20/50 SMA crossover with alert`) ask local `qwen3:8b` (`think:false`) to write TradingView Pine Script v5 code — an `indicator()` with inputs/plot/alert conditions, or a backtest-ready `strategy()` with fixed 0.1% commission / 10% position size / $10,000 starting capital baked into the prompt — from a plain-English description, returned in a fenced code block with a "draft, not compiler-verified" caveat (no local model here is code-tuned). Slack/text only (broader than `GENERATE_IMAGE`'s Slack-only gate since this is plain text, not a file upload); voice and the public web chat get a decline reply. The strategy prompt's "convert the indicator above" can't be implemented literally — the router keeps no cross-message memory outside the confirm/cancel TTL — so `PINE_STRATEGY` always generates a fresh `strategy()` from its own description rather than chaining off a prior `PINE_INDICATOR` reply.
- **Stock fundamentals, earnings, valuation, technicals & risk-flags reports** — five SEC/Yahoo-sourced report tiers, separate from the voice-facing `STOCK_ANALYSIS` command above. **Category 1** (`ops/stock_fundamentals.py`, on-demand only, `python ops/stock_fundamentals.py [--tickers ...]`, plus `regenerate(ticker)` called automatically by Category 2/3/5 after each of their own successful reports so the current-price/Timeliness Flag stay fresh on new SEC activity — Category 4 does not call it, since it isn't SEC-gated): a self-contained "Category 1 Fundamental Snapshot" HTML file per ticker in `content/stock-fundamentals/` (gitignored) — 15 sections (Timeliness Flag through Red/Yellow/Green Flags, with 🟢/🟡/🔴 icons and an NZT generation timestamp), 10 fully deterministic from SEC XBRL company-facts/10-K text (incl. best-effort Products/Services + geographic segment-revenue extraction, balance-sheet health, quality of earnings, a latest-FY valuation snapshot using current price), 5 narrative sections (business, risk highlights, moat, forward watchlist, ownership) grounded in extracted 10-K/DEF 14A text via local Ollama (`lfm2.5`, `num_predict=1500`, no `think:false` — unlike the model below, it doesn't cleanly honor that param; its bullet output needed a `**`-stripping fix to avoid leaking markdown into the HTML). **Category 2** (`ops/stock_earnings.py`, scheduled task "VoiceOS Earnings Watch", 1:00 AM NZT): reactively polls SEC EDGAR for each watchlist ticker's latest 8-K with item 2.02 ("Results of Operations") — accession-based dedupe, not a fixed date check, so a late run still catches up — and generates a quarterly report (results summary, EPS-only beat/miss vs. Nasdaq's free consensus, guidance trajectory, 4-quarter segment trends, buyback/dividend updates) to a dedicated Notion database ("股票季度業績 Quarterly Earnings", same `ops/notion.json` integration). Revenue/EPS are regex-extracted from the 8-K's EX-99.1 press release exhibit (found via the accession's `-index-headers.html`, not the 8-K's own cover-page primary document) rather than XBRL, which lags the 8-K until the 10-Q files. Uses `qwen3:8b` (`think:false`), not `lfm2.5` — benchmarked separately, `lfm2.5` returned empty content on the segment-trends prompt. A companion scheduled task, "VoiceOS Earnings Watch Notify" (`ops/earnings_watch_notify.py`, 10:00 AM NZT), pushes one ntfy alert if the 1 AM run generated anything, deliberately split so the phone isn't paged overnight. **Category 3** (`ops/stock_valuation.py`, scheduled task "VoiceOS Valuation Watch", 1:30 AM NZT — staggered 30 min after Category 2, same reactive 8-K trigger and accession-based dedupe, own state file `asr/logs/valuation_watch_state.json`): multi-method valuation (trailing + 5-year-median multiples, beta/WACC, full DCF with terminal value, reverse-DCF implied growth via bisection, a WACC×terminal-growth sensitivity matrix, peer comparison against a user-curated `ops/peers.json`, and EV/Revenue-only sum-of-the-parts) to a dedicated Notion database ("股票估值 Valuation", same `ops/notion.json` integration, `valuation_database_id`). Forward P/E was dropped (no free forward-consensus source); prompts 17-21 (DCF/reverse-DCF/sensitivity/glide path) are 100% deterministic Python, zero LLM calls — only the multiples/peer/sum-of-parts commentary is narrated, by `qwen3:8b`. A `dcf_negative_fcf_warning` is prepended to the report's methodology whenever after-tax operating margin can't cover capex intensity (real, confirmed case: TSLA's FY2025 figures), rather than showing an unexplained negative fair value. **Category 4** (`ops/stock_technicals.py`, scheduled task "VoiceOS Technicals Daily", 09:30 NZT — replaces the older, thinner `ops/stock_daily.py` price/SMA/RSI/AI-take job at the same slot): not SEC-gated like Category 1-3 — needs only Yahoo Finance price data, so `SPCX` stays in the watchlist here (unlike `sf.EXCLUDE_NO_SEC_FILINGS`), only its earnings-volatility section N/As per-ticker (not by exclusion) when a ticker has no SEC filings. Five sections per ticker: a weekly chart read (50/200-week EMA, 14-period weekly RSI, 52-week range, fractal-pivot support/resistance, LLM trend/momentum/swing-thesis narrative), a daily chart read for swing entries (50/200-day SMA, daily RSI, daily support/resistance, LLM Long/Short/Wait verdict extracted from the reply), volume & accumulation (On-Balance Volume trend vs. 20-day volume MA, LLM confirming/diverging read), relative strength vs SPY (3-month/6-month return differential — 100% deterministic, no LLM), and historical-only earnings volatility (average realized earnings-day price move across up to 8 real quarterly 8-Ks — Yahoo's options endpoint (`v7/finance/options/...`) was live-tested and confirmed 401-unauthenticated, so no implied-vs-historical comparison is possible). Narrative sections use `qwen3:8b` (`think:false`), same rationale as Category 2/3. Writes to a dedicated Notion database ("股票技術分析 Technical Analysis", `technicals_database_id`). `SPCX`'s thin real trading history (8 weekly / 30 daily bars, live-confirmed 2026-07-28) legitimately N/As its EMA/weekly-RSI/SMA/relative-strength sections — every math helper returns `None` on insufficient data rather than a guessed number. **Category 5** (`ops/stock_risk_flags.py`, scheduled task "VoiceOS Risk Watch", 2:00 AM NZT — staggered after Category 2/3, reactive on each ticker's latest **10-K** rather than 8-Ks, own state file `asr/logs/risk_watch_state.json`, accession-based dedupe): the "forensic" tier — top 3 risk factors de-jargoned with a plain-English $-impact framing, off-balance-sheet liabilities (operating leases/pensions/contingencies, best-effort footnote extraction via keyword windows, N/A with no LLM call when nothing is found), goodwill-impairment risk (goodwill as % of equity, deterministic >30% flag, plus LLM-read impairment-assumption commentary), receivables-vs-revenue trend/DSO and inventory-vs-revenue trend (both 3-year, 100% deterministic — a new `_xbrl_multi_year()` helper pulls each tag's full historical fact array across all 10-Ks, deduped by period-end, since `stock_fundamentals.py`'s existing `_xbrl_series` is scoped to one accession and only yields ~2 years for balance-sheet tags), debt maturity schedule (Y1-Y5+thereafter buckets, deterministic refinancing-risk flag vs. cash+STI+OCF), and auditor changes/going-concern (shown as **raw cited excerpts, never LLM-paraphrased** — a going-concern flag must never be softened or missed by a summarizer). Deliberately minimizes LLM usage vs. Category 1-4: sections 4-6 are zero-LLM by design, and section 7 avoids narration entirely. Uses `qwen3:8b` (`think:false`) for the sections that do call the LLM. Writes to a dedicated Notion database ("股票風險與紅旗 Risk & Red Flags", `risk_database_id`). Unlike Category 2/3's `STALE_DAYS=30` first-run guard, Category 5 has none — a 10-K's risk factors aren't time-sensitive "news," so the first-ever encounter of any ticker always generates a report.
- **Mag 7 risk dashboard** (`ops/stock_risk_dashboard.py`, "Category 6", scheduled task "VoiceOS Risk Dashboard Daily", 10:00 NZT — 30 min after Category 4): a 10-KPI composite risk score (Fundamental Health, Earnings Quality & Surprise Stability, Revenue & Margin Trajectory, Balance Sheet & Debt Maturity Risk, Cash Flow & Dividend Coverage, Valuation vs History & Peers, Technical Trend & Momentum, Volatility & Event Risk, Market & Peer-Relative Pressure, Red Flags & Accounting Risk), each 0-1 with a Red/Amber/Green light (≥0.70/0.40-0.69/<0.40), composite = round(10 × mean of available KPIs, 1). Not a sixth independent report tier — reuses Category 1-5's already-built deterministic helpers directly, in-process (imports `sf`/`se`/`sv`/`st`/`srf`), rather than calling their `build_report()`/`poll_and_generate()` entry points, which would re-trigger LLM narration, Notion writes, and Category 2/3/5's reactive state-file dedupe. A pure daily snapshot, not reactive — valuation/technical inputs move every trading day even when nothing new has filed with the SEC. KPI 2 reads Category 2's own `asr/logs/earnings_history.json` directly for multi-quarter surprise stability, weighted `min(1, n/4)` so a thin history (1-2 quarters, as of first ship) never fakes confidence. KPI 7's Long/Short/Wait-equivalent verdict is deliberately recomputed as a 100%-deterministic SMA/RSI rule rather than calling Category 4's own `_section_daily()`, which is LLM-derived — avoids a redundant qwen3:8b call ~30 min after Category 4's own run already made one for the same trading day. KPI 9 ("Market & Peer-Relative Pressure") is an explicit, labeled approximation — no sector classification, macro calendar, or regulatory tracking exists anywhere in this codebase, so it's built from relative-strength-vs-SPY (market proxy) and peer-multiple spread from `ops/peers.json` (sector-stress proxy); never presented as real sector/macro data, in Notion or the dashboard UI. Tickers with no SEC filings (`SPCX`) get every SEC-dependent KPI (1,2,3,4,5,6,10) marked N/A; KPI 7/9 also legitimately N/A for `SPCX` today (its ~30-bar trading history doesn't cover SMA200/63-day relative-strength windows) — a real, live-tested finding, not by design exclusion. One `qwen3:8b` (`think:false`) call per ticker for a 3-sentence summary, fed only the already-computed KPI scores/lights/details — narrates locked-in numbers, never re-judges them. Writes one Notion page per ticker per day (append-only, `risk_dashboard_database_id`) — a human-browsable historical log, same role Notion plays for every other category — **and** a local JSON snapshot (`dashboard/data/latest.json`, gitignored) that the Next.js frontend actually reads; Notion is not in the live read path.
- **Mag 7 dashboard frontend** (`dashboard/`, Next.js App Router, its own `package.json`/Vercel project (project name `dashboard`, `dashboard-pink-psi-88.vercel.app`) — `gateway/` (the real project name is `a-chicken-talking-to-a-duck`, not "gateway"; see memory: vercel-gateway-url for a CLI-linking gotcha) is a flat zero-config Vercel Functions project and can't host a framework app without its build/routing taking over everything there): a fully static site with **no runtime API calls and no secrets in Vercel env at all** — reads `dashboard/data/latest.json` at build time via Node `fs` (`app/lib/data.ts`), baked directly into the static HTML. `next.config.mjs` sets `basePath: "/dashboard"` and `gateway/vercel.json` rewrites `/dashboard`/`/dashboard/:path*` to the dashboard project's production URL, so it's also reachable at https://a-chicken-talking-to-a-duck.vercel.app/dashboard (a routing-layer proxy only — the two Next.js/Functions codebases stay fully separate). Publish is automated via `ops/deploy_dashboard.py` (run by the "VoiceOS Risk Dashboard Daily" scheduled task in place of calling `stock_risk_dashboard.py` directly): generates the watchlist, then runs `vercel --prod --yes` in `dashboard/` — but only if at least 1 ticker succeeded, so a fully-failed run (e.g. SEC/Yahoo both down) leaves the last good publish live instead of pushing an empty dashboard. Manual publish (`python ops/stock_risk_dashboard.py` then `cd dashboard && vercel --prod`) still works standalone for ad-hoc regeneration. The gateway rewrite itself only needs redeploying if the dashboard project's own URL ever changes. (An earlier version of this frontend fetched the Notion database live at request time via a narrow-scope integration token; changed same day, before ever shipping, because generating locally then publishing a static snapshot needs zero credentials in a public Vercel project at all — strictly simpler and matches this project's own established `ops/generate_homepage.py` → committed static file pattern.) Plain CSS, no Tailwind/component library — same `--bg`/`--fg`/`--muted`/`--line`/`--accent` custom-property convention as `gateway/public/index.html` and the Category 1/4 HTML reports, for light/dark support with zero JS toggle logic. No voice integration (out of scope for this pass).
